maintenance runner, the built-in driver list and adapter infrastructure, and the
`managedProvider` tests are ported and gated. **Left for after T09 merges:**
`ProviderAuthService.ts` and `providerInstallation.ts` (see "Left for after T09").

## What T22 should call

All paths are `turin_providers::...` unless noted.

1. **Host.** `let live = DesktopProviderHost::new(base_dir, cwd, initial_settings, should_run_background_work)?;`
   (`turin_provider_core::provider_host_live`). Then
   `let settings = live.settings_handle(); let host = Arc::new(live.host);`.
   Drivers take `Arc<ProviderHost>`; keep `settings` to publish every settings
   write: `settings.update_settings(next).await`. That is what rebuilds instances
   and re-probes on a `binaryPath` change.
2. **Drivers.**
   `built_in_drivers::built_in_drivers(host.clone(), BuiltInDriverSlots { codex: None, opencode: None })`
   gives `Vec<Arc<dyn ProviderDriver>>` (Claude, Cursor today). After T09 merges, fill
   `codex: Some(Box::new(|host| Arc::new(CodexDriver::new(host))))`. The OpenCode
   driver (not on main; `provider-opencode` is transport only) uses `opencode` the
   same way. An empty slot leaves its configured instances as `unavailable` shadow
   snapshots. A slot that builds the wrong kind panics at boot.
3. **Instance registry.**
   `let hydration = ProviderInstanceRegistryHydration::new(drivers, &host).await?;`
   (`turin_provider_core::provider_instance_registry_hydration`). Hold it for the
   app's life: dropping it stops the settings watcher. `hydration.registry` is the
   `Arc<ProviderInstanceRegistry>`; use `get_instance(&id)` for
   `orchestration_adapter`, `text_generation`, `auth`, `snapshot_for_cwd`.
4. **Model manifest.**
   `let manifest = Arc::new(ModelManifest::new(&host.paths.state_dir, update_checks));`
   where `update_checks` is an `UpdateChecks`. Reuse
   `turin_provider_claude::claude_managed_provider::provider_update_checks(host.clone())`
   (reads `enableProviderUpdateChecks`). The Claude driver builds its own manifest
   under the same state dir; both read the same disk cache.
5. **Registry.**
   ```rust
   let registry = Arc::new(ProviderRegistry::start(
       hydration.registry.clone(),            // Arc<ProviderInstanceRegistry> as Arc<dyn ProviderInstanceSource>
       manifest.clone(),
       ProviderRegistryOptions {
           provider_status_cache_dir: PathBuf::from(&host.paths.provider_status_cache_dir),
           t3_code_version: env!("CARGO_PKG_VERSION").to_owned(), // the real app version
           clock: None,
       },
   ).await);
   ```
   `start` reads the per-instance disk cache and the live snapshots; it runs no
   probe. Dropping the registry aborts its tasks.
6. **Using it** (all on `Arc<ProviderRegistry>`):
   - list: `registry.get_providers()` (sync, latest merged snapshots, includes
     unavailable shadows);
   - live updates: `registry.stream_changes()` returns a `BoxStream<Vec<ServerProvider>>`
     of the full list per change (subscribes when called; each subscriber gets
     every update);
   - refresh: `refresh(None)` (all, concurrent callers share one pass),
     `refresh(Some(&kind))` (default instance of a kind), `refresh_instance(&id)`;
   - skills and slash commands for a cwd:
     `refresh_workspace_snapshot(RefreshWorkspaceSnapshotInput { instance_id, cwd, fresh })`;
   - maintenance: `get_provider_maintenance_capabilities_for_instance(&id, &kind, fresh)`,
     `set_provider_maintenance_action_state(&id, ProviderMaintenanceActionKind::Update, state)`.
   - **Check and auth status** is the `ServerProvider` in the list: `installed`,
     `status`, `auth.status`, `message`, `version_advisory`, `compatibility_advisory`,
     `update_state`. Provider login flows are the instance's `auth`
     (`ProviderAuthController`), see below.
   - **Start a session:** `hydration.registry.get_instance(&id)?.orchestration_adapter.open_session(input)`
     (the registry does not wrap this; upstream does not either). The orchestration
     layer routes by `instance_id`.
7. **One-click updates.**
   ```rust
   let runner = Arc::new(ProviderMaintenanceRunner::new(ProviderMaintenanceRunnerDeps {
       registry: registry.clone(),                 // Arc<dyn MaintenanceRegistry>
       manifest: manifest.clone(),                 // Arc<dyn MaintenanceManifest>
       spawner: Arc::new(TokioCommandSpawner),
       versions: Arc::new(LiveMaintenanceVersions::new(Arc::new(ProviderLatestVersions::default()), reqwest::Client::new())),
       t3_code_version: env!("CARGO_PKG_VERSION").to_owned(),
   }));
   runner.update_provider(kind).await            // or ProviderUpdateTarget { provider, instance_id, target_version }
   ```
   Returns `ServerProviderUpdatedPayload { providers }` or `ServerProviderUpdateError`
   (already running, or no one-click update). Progress shows up as `update_state` on
   the provider via the registry stream.
8. **Shared adapter infrastructure.**
   `let infrastructure = ProviderOrchestrationAdapterInfrastructure::new();` once.
   Give `infrastructure.continuation_requests` (the same `Arc`) to both the
   orchestration continuation worker and any adapter that offers requests. Claude's
   driver does not take it yet (T10d note), so nothing consumes the queue today.
9. **Boot sweep.** `project_settings_override_sweep::sweep(&settings_service, &project_store).await`.
   Best-effort; call it before building the registry.

## Left for after T09

- **`ProviderAuthService.ts`** (304 lines + `ProviderAuthService.test.ts`). It routes
  login/logout to an instance's `ProviderAuthController` and needs the Codex auth
  surface, so it waits for T09.
- **`providerInstallation.ts`** (163 lines + test). Codex installation is T09's
  (`CodexInstallation`); Antigravity is cut. Port it with a trait the Codex
  installer implements.
- **`providerAuthFlow.ts` is not to be ported here.** T09d already ported it into
  provider-core on `task/T09d-codex-driver`. Do not port it again; use that module
  after the merge. If T09d's version lands after this branch, `ProviderAuthService`
  should call it rather than the old `auth.rs` controller alone.
