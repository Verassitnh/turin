# R1 handoff: provider registry (partial)

Status: **partial**. Ported and gated: model catalog, compatibility policies,
status cache, managed snapshot loop, maintenance command coordinator, built-in
catalog type, project settings override sweep. **Not ported:** `ProviderRegistry`
(the registry T22 needs to list, check, and start providers), the maintenance
runner, provider auth service and auth flow, provider installation, the
adapter infrastructure layer, and the built-in adapter driver list. T22 is
blocked on `ProviderRegistry` (see "Next items").

## What T22 should call

Start from the live pieces on main, in this order:

1. **Model manifest and catalog.** `ModelManifest::new(state_dir, enable_checks)`,
   then `ModelCatalog::new(Arc::new(manifest))`. Per driver:
   `catalog.current(&kind).await` (no network), `catalog.bundled(&kind)` (fallback),
   `catalog.refresh_in_background()` from a provider check.
2. **Classify a draft.** `apply_model_catalog(draft, catalog.as_ref(), matching)`
   reclassifies legacy models and moves the default. Pass `CatalogMatching { family }`
   when the driver's slugs are qualified (for example `vendor.` prefixes).
3. **Compatibility.** Decode the manifest's `compatibility` array with
   `decode_provider_compatibility_policies(&manifest.compatibility.unwrap_or_default())`.
   Then `apply_provider_compatibility(snapshot, remote, bundled, t3_code_version)`
   on every published snapshot. **Pass the real app version as `t3_code_version`.**
4. **Status cache.** `resolve_provider_status_cache_path(cache_dir, &instance_id)`,
   `read_provider_status_cache(path).await`,
   `write_provider_status_cache(path, &provider).await`. Hydrate a fresh probe
   with `hydrate_cached_provider(&cached, &fallback)`. Order a list with
   `order_provider_snapshots`.
5. **Managed snapshot per instance.** Build a `ManagedServerProviderInput<S>`
   (closures for `get_settings`, `check_provider`, `initial_snapshot`, optional
   `enrich_snapshot`; `refresh_interval: None` reads host background settings),
   then `ManagedServerProvider::start(input, settings_stream, host).await`.
   `settings_stream` is `ProviderSnapshotSettingsSource::stream_settings()` from
   `snapshot_settings`. The result implements `snapshot::ManagedServerProvider`.
   Dropping it stops its tasks.
6. **Snapshot source.** Wrap each instance as
   `ProviderSnapshotSource::new(instance_id, driver_kind, Arc::new(managed))`.
7. **Maintenance commands.** `ProviderMaintenanceCommandCoordinator::new(|target| err)`
   and `with_command_lock(target, lock_key, on_queued, run).await`. A second command
   on the same target fails at once.
8. **Boot sweep.** `turin_providers::project_settings_override_sweep::sweep(&settings, &project_store).await`
   (best-effort, logs failures).

Drivers plug in through the existing `ProviderDriver` (`provider-core/src/driver.rs`).
`ManagedServerProvider` is what a driver returns from its snapshot; `CursorDriver`
(`provider-cursor/src/driver.rs`) is already a `ProviderDriver`.

## Next items (in order)

1. **`ProviderRegistry`** (`apps/server/src/provider/ProviderRegistry.ts`, 1147 lines,
   with `ProviderRegistry.test.ts`). T22 needs it for list, status, refresh, and
   start. Blocker for everything below. Its `resolveMaintenance` and
   `refreshInstance` paths call the maintenance runner, so port in this order:
   registry first, then runner.
2. **`providerMaintenanceRunner.ts`** (603 lines + test). Depends on the registry
   and on `package_managed_maintenance` (already on main).
3. **`ProviderAuthService.ts`** (304 lines + test) and `providerAuthFlow.ts`
   (525 lines, not in the R1 scope list). `auth.rs` already holds the controller.
4. **`providerInstallation.ts`** (163 lines + test). Codex installation is T09's
   (`CodexInstallation`), which is not on main. Antigravity is cut. Port with a
   trait the Codex installer implements.
5. **`ProviderOrchestrationAdapterInfrastructure.ts`** (32 lines). Shared
   IdAllocator and continuation-request infra. Depends on the adapters.
6. **`builtInProviderAdapterDrivers.ts`** (47 lines). Lists the drivers. Cursor and
   OpenCode are ready to list; Codex and Claude come from T09d and T10d. Grok, Pi,
   and ACP registry are cut.
7. **Tests not yet ported:**
   - `managedProvider.test.ts` (685 lines, 11 Effect cases). The behaviour is
     implemented in `managed_provider.rs` but has no tests yet. This is a gap.
   - The registry-stream case in `providerCompatibility.test.ts`
     (`a remote policy refresh preserves a newer health result`). Lands with
     `ProviderRegistry`.
   - `ProviderRegistry.test.ts`, `providerInstallation.test.ts`,
     `providerMaintenanceRunner.test.ts`, `ProviderAuthService.test.ts`.
