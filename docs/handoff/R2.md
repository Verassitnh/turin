## Session repoint notes

- `open_session` uses `AcpSessionRuntime::make` with Cursor ACP args and protocol v1 initialize options.
- Duplex/unit tests use `AcpSessionRuntime::from_connected_client` via `CursorSession::from_client`.
- After `session/new` or `session/load`, `adopt_started_session` records `start_result` so `runtime.prompt` / `runtime.cancel` inject the native session id without calling `runtime.start()`.
- Cursor-specific `session/update` → turn projection stays on `runtime.client()` handlers (Weak refs); runtime broadcast pipeline is inactive until `start_result` exists.
- Runtime client hooks use `Weak<Inner>` so dropping `CursorSession` still tears down the child process (regression: `dropping_the_session_kills_the_agent_process`).
