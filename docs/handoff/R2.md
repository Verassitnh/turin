## Findings on the existing T12 adapter

- `crates/provider-cursor/src/session.rs` (3344 lines) does not wrap `AcpSessionRuntime`. It is a Cursor-specific session that calls `turin_acp::AcpClient` directly, with its own turn, card, and permission state. Upstream's Cursor adapter sits on `AcpSessionRuntime`.
- The faithful structure (runtime in `crates/acp`, Cursor adapter on top) is **not** done. Repointing `session.rs` at a new runtime is a large behaviour-changing refactor over 44 tests and T12's QC fixes. It needs a PM decision before it starts. Recommendation: port `AcpSessionRuntime` into `crates/acp`, then migrate `session.rs` in its own slice, keeping its tests as the regression net.

## Blockers and decisions for the next slice

1. **`coreRuntimeEvents.ts` needs the V1 `ProviderRuntimeEvent` shape.** Contracts has `ProviderRuntimeEventV2` (`provider_runtime.rs:1220`) and the `ProviderRuntimeEventBase` / `CanonicalRequestType` types, but no V1 `ProviderRuntimeEvent` union. Confirm with the PM which union the ACP events target before porting it.
2. **`nativeLogging.ts` depends on `provider-core` `ProviderEventLoggers` and `nativeProtocolLogging`.** Those are not in Rust yet. Port them with the runtime or stub the logger trait.
3. **Process-group and cgroup lifecycle in `AcpSessionRuntime.ts`.** Upstream has POSIX process-tree, Linux cgroup, and Windows terminator controllers (`AcpPosixProcessTreeController`, `AcpLinuxCgroupController`). The Rust plan from PORTING.md is `tokio::process` with `kill_on_drop` and a process group, killed on timeout or shutdown. The cgroup and Windows parts should be a recorded Deviation, not a line-by-line port. Needs PM sign-off.
4. **`runtimeModel.ts` remaining parts.** Tool-call state, terminal state, content blocks, plan updates, permission request parsing, MCP tool identity, and load-replay gating (about 1400 lines of source and 58 tests). These feed `AcpSessionRuntime` and should be ported before it.
