## Seams (for T13c / T13e)

`core/context_handoff_delivery.rs` defines two narrow traits. The provider session owner implements them:

- `ContextHandoffStore::persist(&OrchestrationV2ContextHandoff)`: the handoff store write.
- `HistoricalContextInjector::inject(&ProviderAdapterV2HistoricalContext) -> Result<bool>`: native history injection. `false` means the provider refused before reading the prompt.

`deliver_context_handoffs` returns `ContextHandoffDelivery { context, delivered, unsent }`. The caller persists `delivered` (status `inline`) after the provider accepts the turn, and `unsent` if it refuses. `persist_handoffs` does the batch write.

`ContextHandoffService` takes no store and no session. It is pure construction. `ContextHandoffService::from_env()` reads `T3CODE_CONTEXT_HANDOFF_TOKEN_CAP`.

`core/checkpoint_rollback_service.rs` defines the collaborators rollback needs. The owners implement them:

- `ProviderSessionOpener::open(OpenProviderSession) -> Arc<dyn ProviderConversationRollback>`: provider-session open. `ProviderConversationRollback::rollback_thread` is `session.rollbackThread`; return the snapshot's `provider_thread`.
- `RuntimePolicyResolver::resolve(thread, model_selection) -> ProviderAdapterV2RuntimePolicy`: upstream `RuntimePolicyV2.resolve({ thread, modelSelection })`. The pipeline `runtime_policy::resolve` takes a project root and is not this method.
- `ThreadCommandLock::with_lock(thread_id, future)`: `ThreadCommandExecutor` implements it. The future runs while the thread lock is held.
- `CheckpointFiles::{restore, delete_stale_refs}`: T13d `CheckpointService::restore` / `delete_stale_refs` (not on this branch). Git refs themselves live in `turin-git` checkpointing.
- `RollbackRecords::get_thread_records`: provider threads, sessions, checkpoints, scopes, runs, attempts, nodes, provider turns.
- `RollbackEventWriter::write`: `EventSink::write(WriteInput::events)`.
- `RestoreIsolationReads`: shell rows, other threads' checkpoint cwds, live session cwds, and `project_workspace_root` with deleted projects included (`Ok(None)` means the project record is gone). `is_checkpoint_restore_isolated` is in this file. T13d has a sibling port under `reactors/`; keep both until that branch lands, then one should call the other.

## Deviations (add to PORTING Deviations)

- `ContextHandoffService`: preparation is sync and infallible. Upstream's `ContextHandoffPrepareError` wraps `IdAllocator` failures, and the Rust allocator cannot fail. The error type is not ported.
- `ContextHandoffService`: upstream `layer` becomes `new(token_cap)` / `from_env()`.
- `ContextHandoffDelivery`: the budget arrives already resolved as `i64`. Upstream accepted an Effect for it.
- `ContextHandoffDelivery`: upstream's lazy `delivered` / `unsent` Effects are returned as data, and the caller persists them.
- `workflowFileRead`: `HostProcess.HomeDirectory` is an argument, not a global read, so tests run against temp dirs. The real `~/.claude` is never touched by tests.
- `workflowFileRead`: `cause` in the error is stored as the error's text (the contract carries `cause` as an opaque JSON value).
- `workflowFileRead`: the blocking open, stat and bounded read run in `spawn_blocking`, with `O_NONBLOCK` on unix so a FIFO cannot hang the read.
- `CheckpointRollbackService`: collaborators are traits. `IdAllocator` cannot fail, so allocation is not an error path.
- `CheckpointRollbackService`: unexpected-failure `cause` is the error text. Upstream's `Schema.Defect()` holds the thrown value.
- `CheckpointRollbackService`: a missing `itemIdentityVersion` and an explicit null are both omitted. The contract field does not distinguish them.
- `is_checkpoint_restore_isolated`: containment is `Path::starts_with` on canonical paths, which matches `path.relative` after `realpath`.
