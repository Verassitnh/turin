## Left

1. **`projectSettings`, upstream tests not yet ported.** The cases that call `applyServerSettingsPatch`,
   the legacy per-key patch translation, and the t3.json describe block. They need N1's `serverSettings`.
2. **Text-generation fallback wiring.** `resolve_project_settings` and `resolve_worktree_cleanup` take a
   `TextGenerationFallback` argument. Once N1 lands `fallbackTextGenerationModelSelection` in
   `turin_shared`, call sites pass it in (or the parameter is removed and the function is called
   directly). Tests use a stub.
3. **N1's keybindings copy.** `crates/runtime/src/shared_keybindings.rs` (N1) should switch to
   `turin_shared::keybindings` after merge. Not edited here.
4. **`space` shortcut (PM decision).** `KeybindingValue` (contracts) trims and needs 1..=64 chars, so
   `space` cannot be held and is dropped at parse time. Upstream matches it in memory. Decide whether
   `KeybindingValue` should admit `" "`. If it does, `parse_keybinding_shortcut` should use it.
5. **Hooks PATH hydration** (PORTING line 247, tracked to T05b/T22). `read_environment_from_login_shell`
   and `merge_path_entries` exist in `shell.rs`. Calling them once at app startup is not in this branch.

## Decisions to review

- `fancy-regex` as a workspace dependency (see "Dependency added" above).
- Offsets on `ComposerContextReferenceOccurrence` are byte offsets, not UTF-16. Callers in this crate
  slice with the same offsets, so the behavior matches.
- Digit runs above `2^53 - 1` are invalid in the legacy parser, as `Schema.Int` treats them upstream.
- `fancy-regex` backtrack-limit errors read as "no match" in the legacy parser.
