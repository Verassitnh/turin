## Design decisions
- Effect services become async traits / structs with explicit deps (`Arc<dyn …>`); Effect Context values (credential scope, routing credential, interactive) are `source_control_core::ambient` task-locals; spawned work carries `ambient::capture()`.
- Provider errors keep the upstream tag/fields in `cause` JSON (`cause_value` in `github/source_control_provider.rs`); decode failures expose only a fixed message (no raw body).
- `PullRequestError = PullRequestReadError {Operation, Unavailable}` is shared by service and review guides.
- A4 batching uses a small `oneshot` coalescer (10 ms window, 25 per batch) in place of `RequestResolver`; tests use `tokio::test(start_paused = true)` plus a clock following tokio time.
- Cache TTL/coalescing (`Cache.makeWith`) reimplemented as `ContextCache`/`TtlCache` with `Shared` futures, failures never cached.
- GitHub-only: Forgejo/GitLab/Bitbucket/Azure/GitCafe cut; their URL cases assert `None`.
- Settings schema lives beside each host as serde structs, not on the definition (`secret_settings_fields` only).
- Service reads from the rest of the server through small ports in `pull_request/service/ports.rs` (`PullRequestProjectSource`, `RepositoryIdentityResolver`, `PullRequestSettings`); the orchestration crate implements them later.

## Gotchas
- Send/HRTB errors with borrowing closures under `tokio::spawn`: use `&(dyn Fn(..) + Sync)`, manual `FuturesOrdered` windows.
- Two same-named types (`GitHubPullRequestListBatch`, `GitHubPullRequestSearchBatch`) exist in `pull_request_json` and `pull_request_api::list`: import by path.
- `ScriptedHost` panics on any unscripted op ("Unexpected … in a test that supplied none").
- `tokio` `test-util` is enabled via dev-dependencies; `markdown`, `fancy-regex`, `rusqlite`, `turin-persistence` added to `Cargo.toml`.
- Possible upstream bug ported as-is: empty label group skipped as a search qualifier but unsatisfiable in the local fallback filter (A4).
