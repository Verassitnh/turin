## Done

### Group 1: items, nodes, deltas, usage

- `items.rs`: builders for `agentMessage`, `reasoning`, `commandExecution`, `webSearch`, `fileChange`, proposed `plan`, and `turn/plan/updated` todo lists. Ordinals follow `resolveItemPosition`.
- `projection.rs`: notification dispatch and the text-delta coalescer (50 ms assistant and reasoning, 400 ms plan). Turn end flushes buffers and marks running commands interrupted or failed. Token usage drives the provider turn.
- `orchestration_adapter.rs`: a pump task projects frames as they arrive. Frames for a turn not yet registered are parked in order (cap 4096) and drained on registration. Interrupt terminates running background terminals.

### Group 2: MCP and dynamic tools (this session)

- `tool_presentation.rs` (new): the integration path of `CodexToolPresentation.ts` `mcpToolPresentation`, `dynamicToolTitle` (REPL and `Skill`), `dynamicToolSurface` (`sky` calls), and `COMPUTER_USE_TOOL_SOURCE`. Seven unit tests.

- `projection.rs`: running tools are tracked per turn. On turn end they are terminalized as upstream does: interrupted or failed for those ends, cancelled otherwise, and persistent tools only on interrupt or failure.
- Replay test `file_change_replay_maps_first_change_to_file_change_item` pins the `fileChange` mapping from `tool_call_restricted_granular`. No Codex fixture contains an `mcpToolCall` or `dynamicToolCall`, so those paths have unit coverage only.

### Group 3: restart-resume (3 of 3)

- `provider_thread_resume`: the transcript is split at the restart. The second session runs `thread/resume` (excludeTurns) on the native thread, then its turn.
- `thread_rollback_after_restart`: `thread/read`, then resume (the adapter's `revert_thread` does this when the thread is not loaded), `thread/turns/list`, `thread/revert`. The test then resumes explicitly before the next turn.
- `thread_rollback_to_stopped_turn`: an interrupted boundary, with the background-terminal terminate on interrupt.
- `orchestration_adapter.rs` `rollback_turn_count` ports `resolveCodexRollbackTurnCount`. The boundary must be in the thread's own history. A foreign turn is refused. A zero count returns without a request, as upstream does.

**Ownership note:** the `thread/resume` that upstream sends after a revert comes from `ProviderSessionManager` (`holdThreadLoaded` / `runtime.resumeThread`), not from the adapter. The replay test calls `resume_thread` itself to stand in for it. The orchestration layer owns this step.

### Group 4: fork and merge-back (4 of 4)

- `fork_last_turn` ports `resolveCodexForkBoundary`. `lastTurnId` comes from the boundary's native ref. A missing boundary is an error. A boundary without a native ref, with later turns, is refused. The revert-count fallback cannot run here because the trait returns no rollback count.
- `thread_fork_native_continue`, `thread_fork_native_siblings`, `thread_merge_back_continue`, `thread_merge_back_siblings`.
- Merge-back has no adapter counterpart. The handoff text arrives as a plain `turn/start` on the source thread. The `Context handoff (merge_back / fork_delta_summary)` text is built upstream in `ContextHandoffService`, which is the orchestration crate's job.

### What the transcripts show

- Root turn: `item/started` and `item/completed` of `subAgentActivity` (`kind` `started`, then `completed` with id `subagent-completed-<turnId>`). Fields: `agentThreadId`, `agentPath`. `projection::item_started` and `item_completed` currently skip this kind.

- Child thread: a separate thread id (`agentThreadId`) emits `thread/status/changed`, `turn/started`, `item/agentMessage/delta`, `item/completed`, and `turn/completed` for a child turn id. That child turn is not registered by `turn/start`. Under the current pump, its frames are parked forever (cap 4096) and never drained.
- Parked frames are keyed by native turn id. Child turns need a thread→turn registry so they resolve to the parent's root turn context. This changes the parking path in `ingest` and `drain_parked`. Keep the invariant that `project_event` removes a turn while it works and reinserts it. `turn/completed` does not reinsert.
- `subagent_v2_approval` and `subagent_v2_nested_approval`: `item/commandExecution/requestApproval` is raised from the child turn. Its owner must be the child's root turn. Upstream: `approvalOwnerCodexTurn` and `isDescendantCodexTurn` (~L1217).
- `subagent_v2_nested*`: a grandchild. The registry must walk parent links.
- `subagent_continue`: a second `turn/start` on the same subagent.

## Notes for the next agent

- Pump and parking: `ingest` parks any frame whose turn is unregistered, or behind a parked frame for the same turn. A turn that never registers is dropped at the cap. Check this before adding child-turn registration.
- `project_event` removes the turn from `state.turns` while it works and reinserts it. A `turn/completed` does not reinsert. Keep that invariant when adding per-turn state.
- Replay timing: the harness runs frames without delay, so text flushes rarely fire. Assertions use completed items (`assistant_texts`).
- Replay restarts: a second session is the same transcript sliced at the first session's `runtime_exit`. `open_session` and `open_restarted` in `replay_tests.rs` are the helpers.
- Driver: `thread/backgroundTerminals/*` is not in the pinned typed surface. Use `client.raw.request`.
- PORTING rows are updated for every deviation above, including tool presentation and the fork-boundary refusal.
