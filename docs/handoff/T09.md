# T09 handoff: provider-codex

Branch `task/T09-codex-adapter`. Gate: `scripts/check.sh -p turin-provider-codex` passes at the last commit, 46 unit and replay tests.

`main` is merged in. The contracts crate has `dynamic_tool`, `subagent`, `fork`, `handoff`, and `thread_created` turn items.

## Done

### Group 1: items, nodes, deltas, usage

- `items.rs`: builders for `agentMessage`, `reasoning`, `commandExecution`, `webSearch`, `fileChange`, proposed `plan`, and `turn/plan/updated` todo lists. Ordinals follow `resolveItemPosition`. `run_id` comes from `TurnState::run_id()`, which is empty on a child turn.
- `projection.rs`: notification dispatch and the text-delta coalescer (50 ms assistant and reasoning, 400 ms plan). Turn end flushes buffers and marks running commands interrupted or failed. Token usage drives the provider turn.
- `orchestration_adapter.rs`: a pump task projects frames as they arrive. Frames for a turn not yet admitted are parked in order (cap 4096) and drained on admission. Interrupt terminates running background terminals.

### Group 2: MCP and dynamic tools

- `tool_presentation.rs`: the integration path of `mcpToolPresentation`, `dynamicToolTitle`, `dynamicToolSurface`, and `COMPUTER_USE_TOOL_SOURCE`.
- `items.rs` `dynamic_tool`: `mcpToolCall` and `dynamicToolCall` become `dynamic_tool` turn items.
- A clean turn end keeps the turn in `RuntimeState::settled` while it has a persistent dynamic tool or a running command. Its late `item/started` and `item/completed` frames still project, and the turn is released when no work is left. Unit tests cover both.

### Group 3: restart-resume (3 of 3)

- `provider_thread_resume`, `thread_rollback_after_restart`, `thread_rollback_to_stopped_turn`. `rollback_turn_count` ports `resolveCodexRollbackTurnCount`.

**Ownership note:** the `thread/resume` that upstream sends after a revert comes from `ProviderSessionManager`, not the adapter. The replay test calls `resume_thread` itself.

### Group 4: fork and merge-back (4 of 4)

- `fork_last_turn` ports `resolveCodexForkBoundary`. Merge-back's handoff text is built by `ContextHandoffService`, which is the orchestration crate's job.

### Group 5: subagents (6 of 6)

- `subagent.rs` (new): registration from `spawnAgent` (on `item/completed`) and from `subAgentActivity` (`started`), child turns, task updates, `updateSubagentStates`, child user messages, and the child's final answer as the subagent result.
- A child turn is a `TurnState` with `subagent` set. Its `run_id` and `attempt_id` are empty. Its frames project through the same handlers as a root turn. A child's `turn/started` opens the child turn only once its parent thread has an active turn. Upstream's `pendingSubagentTurns` plays this role.
- A child's approval is raised on the top-level turn. Its node and turn item are parented under the top-level subagent, as upstream's `approvalOwnerCodexTurn` does.
- A child that resumes in a later run is reparented to that run (`subagent_continue`).
- Replay: all six pass (`subagent`, `subagent_v2`, `subagent_continue`, `subagent_v2_approval`, `subagent_v2_nested`, `subagent_v2_nested_approval`).

Replay: all 27 `scenarioExpectations` keys in upstream's `CodexReplayFixtures` pass through `ProviderSessionRuntime`. See PORTING.md, provider-codex fixture coverage.

## Notes for the next agent

- Pump and parking: `ingest` parks any frame whose turn is not admitted (`admitted()` in `orchestration_adapter.rs`), or that sits behind a parked frame for the same turn. `drain_parked` repeats until no progress, because a projected `turn/start` can admit a parked frame.
- `project_event` removes the turn from `state.turns` while it works and reinserts it. A `turn/completed` does not reinsert, and a clean one with retained work moves the turn to `state.settled`. Keep that invariant when adding per-turn state.
- Replay timing: the harness runs frames without delay, so text flushes rarely fire. Assertions use completed items and `latest_items`.
- Replay restarts: `open_session` and `open_restarted` in `replay_tests.rs`.
- Driver: `thread/backgroundTerminals/*` is not in the pinned typed surface. Use `client.raw.request`. The driver-side files belong to T09d; this task changed none of them.
