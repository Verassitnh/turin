## Handoff list status

Round 2 items 1, 2, 4, 7, 8 and step 3 are done. Item 3 (model canonicalisation) is still T10d.

Round 3 items:

5. **Wake turns and continuations. Done at the adapter level.**
   - Idle frames park in `WakeState.buffer`: assistant, user, result, `init`, rate-limit, and background frames while the root is idle. Notifications are buffered before the roster and registry see them.
   - Wake evidence (`WakeEvidence`) offers a continuation once per wake (`requested`). Offers fire on a subagent notification, a native turn's `init` or output after a background task's notification, or a result.
   - The offer is `ProviderContinuationRequest { thread_id, provider_thread_id, driver, detail, notification, … }`. `delivery` is `None`, as upstream sets none for Claude.
   - `ClaudeProviderAdapter::with_continuation_requests` injects the queue. The default drops offers.
   - A continuation turn (`created_by: agent`, `creation_source: provider`) sends no prompt. It replays the buffer, the result last. An empty buffer settles it at once. A buffered `init` or native output keeps it open.
   - Background reports (`WakeState.reports`) age out after the turn before last, as upstream does.
6. **Prompt-echo gating. Done.**
   - `PromptEchoMode` (Unknown, Acknowledged, Early, ResultOnly) is per live process. `ActiveTurn` holds the prompt uuid, the held root frames, and the gated-frame count.
   - Root output is held in `early` mode until the echo lands. A result for another turn with no echo of its own is buffered as a wake, with the held frames before it.
   - `claude_compact_after_peer_turn` (echo variant) is wired: `fixture_compact_after_peer_turn_echo_holds_the_peer_turn_for_a_continuation`. The no-echo variant still passes.
   - The fake CLI maps the fixture's expected prompt uuid to the uuid the adapter sent. The real CLI echoes the sent uuid, so the fake now does too.
   - `fail_active` ends the turn with `Claude acknowledged the message but never started a turn for it.`, as upstream does for a `completed` lifecycle with no `started`.
7. **Restart recovery. Done.** `subagent_resumed_after_a_restart_reopens_its_child_thread` runs two processes over one config dir and cwd.

Provider-core: no change needed. `ProviderContinuationRequest` already has every field the offers use. It has no `Debug` impl, which the host may want. Not added.

## Known gaps

- A continuation with no live CLI errors `Claude session is not running`. Upstream reopens a query and drains there.
- Wake state (`buffer`, `eligible`, `tombstones`, `requested`) is not cleared when the process is replaced.
- Idle task_started and progress frames are not projected until a drain replays them. Upstream does the same; the registry projects only notifications while idle.
- `get_subagent_messages` reads the whole subagent transcript. Upstream passes `limit: 1`. Fine for now; a bounded reader would be better.
- Monitor end paths (`endClaudeMonitorTasks`) are partly ported.
- Subagent thinking is dropped. Workflow members have no thread ids.
- The 50 ms flush has no test that waits on the timer.
- The echo mode and the wake path are exercised only through the fake CLI. There is no live-CLI check.

## Notes for whoever picks this up

- `claude_provider_adapter.rs` is now the state machine: `event` (gate), `route`, `gate`, `buffer_wake`, `offer_continuation`, `drain_wake`, `finish_turn`. The pure parts are in `claude_wake.rs`.
- `TurnScope.run_id` is `Option`. `None` means a child-thread item.
- Subagent state lives in `claude_subagents.rs` (`Task`). Restart recovery is `recover_resumed`, which emits nothing; the resume's `task_started` does.
- `ClaudeAdapterV2::subagent_history` needs `config_dir`. It is set from the launch's `CLAUDE_CONFIG_DIR`, so the CLI and the reader agree on where transcripts live.
- Registry state is session-scoped (`ClaudeActor.subagents`). A background subagent reports against the root node of the turn that launched it.
- `ToolCall.output` is the native value (structured if present). `ToolCall.output_fallback` is the content behind a structured value.
- The Claude model regex uses the `regex` workspace crate. Lookahead is unsupported there, so the minor version uses `\b`.
- Build contention: cargo runs take 10-25 s for this crate when the cache is warm.
