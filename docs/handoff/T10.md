## What changed in round 4

**Model canonicalisation** (`claude_subagents.rs`):
- An Agent launch's model goes through `resolve_claude_model_slug` (T10d's catalog). An alias such as `haiku` becomes the catalog slug.
- A snapshot's model (`message.model` on a subagent frame) is canonicalised too. A running subagent that changes model is updated and re-emitted. An unstarted one keeps it with its launch.
- `inherit`: the root's model at top level; a nested subagent takes its owner's model at task_started. The owner's effort is inherited the same way, with the parent's effort as the last fallback.
- `subagent_model_selection` (upstream `claudeSubagentModelSelection`): the selection carries `effort` only when the model offers it. The subagent's `modelSelection` is set, and the child thread copies it.

**Context windows** (`claude_provider_adapter.rs`):
- Compaction `maxTokens` is `resolve_claude_catalog_context_window_tokens` for the selection, null when the catalog does not know it.
- `ProviderSessionRuntime::get_model_context_window` answers the same resolver.

**Tests:**
- `claude_nested_subagent_model` asserts now: both subagents report `claude-haiku-4-5`, both selections are the model alone (Haiku offers no effort), and the nested child thread copies it. The fixture's own note says "Not asserted" for these; our test asserts them.
- The replay harness uses `bundled_claude_model_catalog()`, the catalog the app ships. Expectations that pinned a raw alias or a null window now come from the resolver: `haiku` resolves to `claude-haiku-5-5` in the shipped catalog.
- New unit test `a_model_alias_is_its_catalog_slug_and_a_nested_subagent_runs_on_its_owners`.

## What QC should look at

1. **The routing change.** While the root is idle, frames now park or replay (`claude_provider_adapter.rs`: `event`, `gate`, `route`, `buffer_wake`, `drain_wake`). The idle branches of `background()`, `assistant()`, `user()`, `result()`, `init()` and `rate_limit()` changed. The harness moved to the bundled catalog, so every replay runs against the shipped model data.
2. **The continuation contract for T13e.** The offer is `ProviderContinuationRequest` with `delivery`, `message_id`, `dispatch_if_current` and `clear_if_current` all `None`. The continuation must start on the same live CLI. With no live process it errors `Claude session is not running`.
3. **Restart recovery reads the transcript** through the launch's `CLAUDE_CONFIG_DIR` (`ClaudeAdapterV2::subagent_history`). The reader loads the whole subagent file. Upstream passes `limit: 1`.
4. **Exit determinism (fixed in round 5, `925d29e`).** The session used to emit `Eof` and `Exit` as separate events, so the turn's failure text depended on which came first. It now sends one `Exit` after stdout closes, and `exit_before_result_fails_the_turn` asserts the exact upstream text again.

## Notes for whoever picks this up

- The wake, echo and continuation state machine is in `claude_provider_adapter.rs`. The pure classification and the per-thread state are in `claude_wake.rs`.
- `TurnScope.run_id` is `Option`. `None` means a child-thread item.
- Subagent state is in `claude_subagents.rs` (`Task`). `recover_resumed` emits nothing; the resume's `task_started` does.
- The subagent registry keeps the launch model and effort, so a snapshot that arrives before task_started is not lost.
- `ToolCall.output` is the native value (structured if present). `ToolCall.output_fallback` is the content behind a structured value.
- The Claude model regex uses the `regex` workspace crate. Lookahead is unsupported there, so the minor version uses `\b`.
- Build contention: cargo runs take 10-25 s for this crate when the cache is warm.
