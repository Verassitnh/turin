## Not done / deviations (also in PORTING.md)
- **Text generation (item 5, skipped per PM).** `UnavailableClaudeTextGeneration` returns a not-implemented error. Task N3 owns `textGeneration/*` and replaces it.
- **Skills.** `discoverClaudeSkills` (ClaudeSkills.ts, ClaudeSkillDispatch.ts) is not ported. Skills are empty. The skill and workspace-skill cases in `ClaudeCapabilitiesProbe.test.ts` are not ported.
- **Version advisory.** No latest-version HTTP check (`enrichProviderSnapshotWithVersionAdvisory`). Maintenance is manual-only.
- **Remote model manifest.** Bundled only. No refresh, disk cache, or compatibility policies.
- **Reset-credit coordinator.** Claims are serialized per instance, not per config directory across instances. The request id is kept for one instance.
- **Snapshot refresh.** The driver runs one background refresh at create. Later refreshes come from the registry calling `refresh`. Upstream's TTL-gated background refresh and settings streaming are not ported.
- **Assumptions to confirm.** Attachments dir is `$TURIN_HOME/userdata/attachments` (`TURIN_HOME` or `~/.turin`). Runtime instructions use harness name `Turin`. `McpProviderSessions` and `ProviderContinuationRequests` are not passed to the driver.
- **`ProviderAdapterDriver` SPI impl removed** from `ClaudeDriver`. `ProviderAdapterRegistry::from_drivers` has no Claude caller.
- `providerModelsFromSettings` lives in `claude_provider.rs`, since provider-core does not have it. It should move to provider-core when another driver needs it.
