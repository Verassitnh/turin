## Round 7 (this pass)

- **Child threads and child turns, v1 and v2.** A `task` call reveals its child session. The child app
  thread and provider thread come from provider-core's `make_subagent_child_thread`, as T10 does. A
  child's turn opens under a `root_turn` node (v1: its user message; v2: `session.execution.started`).
  The prompt projects as a user message. The child's idle (v1) or execution end (v2) settles the node
  and the provider turn. The `session.created` link records ownership only, so the link and the task
  key one subagent record on the task node.
- **Respond retry (v2).** `respond_to_runtime_request` keeps the pending entry until the reply
  succeeds. A failed reply leaves it answerable. A second answer while one is in flight is refused.
  Test: first reply 500, retry lands. (Verified by reasoning against the old code, which removed the
  entry first; not re-run against the old code.)
- **Wake notification (v2).** The wake's continuation carries `background_work_notification` built
  from its reports: label, child thread, outcome.
- **Child tool routing (v2 fix).** A child session's tool calls were dropped. Child turns now live in
  their own map.

## For T13e: continuation queue

`OpenCodeV2Session::set_continuation_requests(Arc<ProviderContinuationRequests>)`. Call it after
`open`. The default is `dropping()`, so offers are lost until it is set. `open` returns `Arc<Self>`,
so this is a setter, not a builder like T10's. Continuations start from the wake's message id and
replay the parked events; they carry no prompt.

## Open

- Grandchild threads: a task inside a child turn gets no child thread on v1 or v2.
- A child turn is not closed when its parent turn ends. It closes on its own idle or execution end.
- Compaction has no node; upstream emits only the turn item, so none is added.

## Cut: v2 inbox and wake continuations (not to be ported)

PORTING.md Deviations lists `provider-opencode/adapter/v2.rs` inbox and wake continuations as
**Cut**: "No inbox or scheduler in Turin yet." Nothing in `crates/` implements an inbox or a
scheduler. This pass did not start it. An earlier draft of this handoff proposed porting it;
that was wrong.

If the cut is ever lifted, the upstream reference is `server/v2/adapter.ts` (`offerWake`,
`finishTurn`, `onWake`, and the `session.inbox.*` handling). The replay fixtures are
`apps/server/src/orchestration-v2/testkit/fixtures/opencode2_inbox` and related scenarios, which
need the orchestrator harness in `crates/orchestration`.
