   - v1: text and reasoning nodes, assistant `message.updated`, tool `tool_call` nodes,
     `todo.updated` → todo node + `plan.updated` + todo item, approval request nodes at
     `approvalNode(requestId)`. Item ordinals are stable per native item (upstream `itemOrdinal`).
     A user's echoed text is no longer an assistant message. Replay test:

     `tool_call` node. Approval/user-input requests emit a waiting node. Replay tests:
     `v2_text_blocks_and_tools_emit_node_and_message_records`,
     `v2_approval_request_emits_a_waiting_node_at_the_approval_id`.

     child-session user message projection (`projectChildUserPart`), the compaction node

## Not started: v2 inbox and wake-continuation state machine

Upstream: `packages/provider-opencode/src/server/v2/adapter.ts` (≈75 `wake` and 35 `inbox`
references; `offerWake` ~1701, `finishTurn` ~1717, `onWake` ~2404, inbox events ~2666–2689,
`session.inbox` calls ~3201).

Upstream tests for it are **not** in `adapter.test.ts`. They are orchestrator replay scenarios in
`apps/server/src/orchestration-v2/OpenCode2OrchestratorV2.integration.test.ts` with recorded
transcripts under `testkit/fixtures/opencode2_inbox`, `opencode2_background`,
`opencode2_nested_background`, `opencode2_resume_after_restart`. Those need the orchestrator
harness, which lives in `crates/orchestration`, not in this crate. The assertion file
`testkit/fixtures/opencode2_inbox/output.ts` lists the expected run statuses and input intents
(`turn_start`, `steer`, `queued_turn`).

Suggested plan: (a) port the inbox/steer bookkeeping as pure state in `adapter/v2_inbox.rs`
with unit tests driven by the transcript's `session.inbox.*` events; (b) port wake offers and
continuation turns; (c) replay the transcripts through the orchestration harness once it exists.
