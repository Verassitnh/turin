# T11 handoff: opencode adapter (round 5 state, kept for reference)

Branch `task/T11-opencode-adapter`, not pushed. Gate `scripts/check.sh -p turin-provider-opencode`
is green at HEAD (141 tests). Text generation is not ported (see PORTING.md Deviations).

## Done this pass

1. **Node, message, plan records** (`adapter/records.rs` holds the shared builders).
   - v1: text and reasoning nodes, assistant `message.updated`, tool `tool_call` nodes,
     `todo.updated` → todo node + `plan.updated` + todo item, approval request nodes at
     `approvalNode(requestId)`. Item ordinals are stable per native item (upstream `itemOrdinal`).
     A user's echoed text is no longer an assistant message. Replay test:
     `v1_text_reasoning_tool_and_todo_emit_node_message_and_plan_records`.
   - v2: text blocks use upstream's stream schema (`assistantMessageID`, `ordinal`, `delta`,
     ended `text` is final). The old code keyed on `id`/`partID`, which the real events do not
     carry. Native id is `${assistantMessageID}:${kind}:${ordinal}`. Tool calls emit a
     `tool_call` node. Approval/user-input requests emit a waiting node. Replay tests:
     `v2_text_blocks_and_tools_emit_node_and_message_records`,
     `v2_approval_request_emits_a_waiting_node_at_the_approval_id`.
   - Not yet done (both generations): `subagent` nodes, `root_turn` nodes for child turns,
     child-session user message projection (`projectChildUserPart`), the compaction node
     (`emitCompaction`). Request resolution emits no node or item completion: v1's
     `resolve_request` updates only the request, and v2 emits `RuntimeRequestUpdated` on
     creation only.

2. **v2 model catalog in the snapshot.** `open_code2_catalog.rs` ports `openCode2Catalog.ts`
   (provider names read in parallel, 3s bound, unnamed providers keep the id).
   `snapshot::build_open_code2_snapshot` builds the 2.x draft (`checkOpenCode2`).

## Cut: v2 inbox and wake continuations (not to be ported)

PORTING.md Deviations lists `provider-opencode/adapter/v2.rs` inbox and wake continuations as
**Cut**: "No inbox or scheduler in Turin yet." Nothing in `crates/` implements an inbox or a
scheduler. This pass did not start it. An earlier draft of this handoff proposed porting it;
that was wrong.

If the cut is ever lifted, the upstream reference is `server/v2/adapter.ts` (`offerWake`,
`finishTurn`, `onWake`, and the `session.inbox.*` handling). The replay fixtures are
`apps/server/src/orchestration-v2/testkit/fixtures/opencode2_inbox` and related scenarios, which
need the orchestrator harness in `crates/orchestration`.
