## Out of scope (crates/acp), for the PM

- `crates/acp/src/protocol.rs:327-333`: the writer loop holds `Arc<ConnectionInner>`, so it never exits on termination. Needs a termination hook or a weak handle.
- `crates/acp/src/process.rs:139-149`: `ProcessGuard` kills and `waitpid`s a pid already reaped on EOF. Gate the kill and waitpid on a reaped flag.
- `crates/acp/src/client.rs`: `prompts` keeps a stale entry when `prompt()` is dropped mid-flight. Turn drop safety in provider-cursor covers the turn state, not this entry.
- `on_termination` is internal to acp. Open cards are resolved through the prompt error path instead of a termination hook.

## Known gaps (also in PORTING.md Deviations)

- `cursor/task` and `cursor/generate_image` are acknowledged, not projected. Capabilities say `emits_subagent_lifecycle` is false. Upstream emits `subagent.updated` and a subagent item. Porting that needs a child-thread model.
- Ask fallback (`<id>_q<n>` permissions): each per-option `allow_once` collapses to the first option, because `ProviderApprovalDecision` has no per-option id.
- Runtime and approval policy are not applied. Cursor's own `permissions.allow` and approvalMode decide.
- Upstream tests that are SDK-shaped (directory trees, lint diagnostics, MCP tool names) have no ACP equivalent in this port. Only the failed-search case is ported literally.
