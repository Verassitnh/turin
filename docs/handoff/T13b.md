## Design decisions / deviations (add to PORTING.md Deviations; not yet done)
- Orchestrator + `ThreadLaunchService` + legacy V1 importer are cut or behind `OrchestratorPort`.
- `ProjectionApplier` trait is the T13a seam (normalize_turn_item, apply_event, apply_project_event, schema_version).
  T13a must implement it with `ProjectionStore::apply_in_tx` + `turn_item_position_store::allocate_in_tx`.
- `event_sink.rs` duplicates persistence's private `append_project_event` (+`infer_actor_kind`); ask persistence owner
  to expose `append_project_event_in`.
- Dispatch-mode limit is an explicit `Option<&DispatchModeLimit>` arg, not ambient context.
- `ThreadManagementService` read pass-throughs and legacy importer hooks dropped.
- Publish lane is taken before the tx (not at its end); SQLite has one writer so order is identical.
- `crates/orchestration/src/pipeline/mod.rs` has `#![allow(clippy::result_large_err)]` (PersistenceError is big).

## Gotchas
- macOS `sed -i ''`; no `timeout` command. Never `rm -rf target` (symlink). One cargo at a time (throttled).
- `ChatAttachment` limit helper: `get_provider_attachment_limit_error`. Shell fixtures need `hasActionableProposedPlan`,
  `providerInstanceHistory`, `itemCount`, `visibleItemCount`, `messageCount`.
- Event ids in test fixtures must be unique per event (sqlite constraint 2067 otherwise).
- Contract double-options: `Some(None)` serializes `null`.
