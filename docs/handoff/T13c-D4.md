# T13c-D4: thread.delete, thread.fork, thread.merge_back

Branch `task/T13c-D4`, from `task/T13c-orch-core` at e3e1205. Status file for item D4 of
`docs/handoff/T13c.md`. That file is not edited here, since parallel agents touch it.

## Done

- `thread.delete` (`core/orchestrator/thread_delete.rs`). Reads the records the planner needs
  (runs, attempts, nodes, runtime requests, subagents, provider sessions) and the thread's
  attachment ids. Calls the ported `pipeline::thread_deletion::plan_thread_deletion` and records
  its events and effects. The planner is not re-ported.
- `thread.fork` (`core/orchestrator/thread_fork.rs`). Port of `dispatchThreadFork`. Resolves the
  source point (`latest_stable`, `run`, `checkpoint`), refuses a missing or non-forkable run with
  upstream's messages, then calls the ported `pipeline::thread_fork_service::plan`. Emits
  `thread.created` and `context-transfer.created`.
- `thread.merge_back` (`core/orchestrator/thread_merge_back.rs`). Port of
  `dispatchThreadMergeBack`. Guards: the source is a fork of the target, the source run is
  provider-finished, and a fork transfer exists. Supersedes pending merge-back transfers for the
  same pair, then emits `context-transfer.created`.
- Shared source-point helpers (`run_for_source_point`, `provider_thread_for_run`,
  `context_source_point_for_run`) live in `thread_fork.rs` and are used by merge-back.
- Routing: three `if ...::decide` arms in `core/orchestrator/dispatch.rs::decide`, and three
  `mod` lines in `core/orchestrator.rs`.
- Shared seams, additive only: `RecordField::Checkpoints` and `RecordField::ContextTransfers`
  (`pipeline/orchestrator_port.rs`), mapped in `core/orchestrator.rs::projection_record_field`.
- Test harness `core/orchestrator/test_harness.rs` (`#[cfg(test)]`). It keeps the projection
  store, so tests can seed run rows with `projection::test_support`.
- `core/orchestrator/tests.rs`: the "kind without a handler" test used `thread.delete` as its
  unported kind. `thread.delete` is now ported, so the test uses `thread.model-selection.set`
  (D3, still unported). Same assertions.

## Not ported, or deviations

- **Dispatch mode limit** (`refuseAboveDispatchModeLimit`, upstream 3572, used by fork and
  merge-back). `OrchestratorPort::dispatch` takes no `DispatchModeLimit` yet. Message dispatch
  (F) owns it. So a fork or merge-back is never refused on a mode limit here. Add the check when
  F threads the limit into `dispatch`.
- **Upstream integration tests not ported.** `testkit/ThreadFork.integration.test.ts` and
  `testkit/ThreadMergeBack.integration.test.ts` drive real provider replay (Codex and Claude
  fixtures). They need the provider runtime, so the coverage here is decider-level on seeded
  projections. `ThreadForkService.test.ts` is covered by `pipeline/thread_fork_service.rs`'s own
  port.
- **Deletion planner tests** are upstream `ThreadDeletion.test.ts`, already in
  `pipeline/thread_deletion/tests.rs`. The tests here only check the command path.

## Gotchas

- Fork and merge-back each emit two events on the target thread for one command. Both use
  `Decision::event_id(thread, command)`, as upstream's `makeEvent` does. The fork test commits both
  events, so the ids do not collide in the event store.
- Stored events wrap the domain event: read `stored.event`, not the stored record itself.
