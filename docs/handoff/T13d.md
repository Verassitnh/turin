## Not wired (the app layer owns these)

- **Loops.** Sync sweep: one-minute `sweep(All)` plus `request_sync` queue. Thread PR service: `periodic_request()` each minute, `refresh(...)` on `request_for_event(...)`. Watch reactor: `sweep()` every `SWEEP_INTERVAL`. Upstream starts each after startup recovery; the app does that ordering.
- **Event subscriptions.** Upstream feeds the sync reactor from `thread.pull-request-link-updated`, `thread.pull-request-synced`, `turn-item.updated` (close commands), `run.updated`, plus T07's state-change stream. This crate exposes the pure mapping (`ThreadPullRequestService::request_for_event`) but not the subscriber loop.
- **Production `ProjectionApplier`.** No adapter from `ProjectionStore` to the sink's `ProjectionApplier` exists on main. The capture tests use a test-only one. Whoever wires the sink needs it.
- **Serialisation.** The thread PR service's `refresh` takes a lock in place of the drainable worker. The sync sweep's `request_sync` does not queue a sweep.

- `VcsProcess` permits are RAII guards held for each run. Code review found no leak.

## Gotchas

- `UtcDateTime`'s field is private: use `as_datetime()`.
- `ThreadManagementService` has no inherent `dispatch`: call it on the core through `Deref`.
- `OrchestrationV2InternalCommand` owns `thread.pull-request-watch.sync`. Dispatch it as `OrchestrationV2ServerCommand::Internal`.
- `ThreadNativeStackKind` is a unit-struct string literal, not an enum.
- Checkpoint numstat is NUL-delimited. Ordinal-0 capture diffs a ref against itself.
- `main` moves often. Merge at each clean commit; `git merge-base --is-ancestor main HEAD` confirms.
- A shell-shaped test fixture needs the run and message fields too. `projection::test_support::thread` is an event payload: `branch_thread` in `thread_pull_request/tests.rs` adds `status` and the rest before decoding.
- Upstream's `resolve(root, {refresh})` is `RepositoryIdentityResolver::resolve(root, refresh)` on the Rust port. Callers that pass no options pass `false`.
