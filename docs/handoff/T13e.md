## Continuation consumer (`core/provider_continuation_service.rs`)

Consumes provider-core `ProviderContinuationRequests`. Adapters (T09 Codex, T10 Claude) offer; this
service takes and dispatches. Contract the adapters rely on:

- **Wake** (no `delegated_completion`): one internal `message.dispatch`, `queue_after_active`,
  `created_by: agent`. `creation_source` is `provider` unless `delivery == MessageText`, which is
  `server`. A `provider` wake makes ClaudeAdapterV2 attach the buffered CLI output and drop the text,
  so a `MessageText` wake must never carry it. Notification defaults to `background_task` /
  `updated` / "Background activity updated". `message_id` from the adapter is used when set.
- **Delegated completion** (`delegated_completion` set): dispatched as a server-owned queued
  message, not through `dispatch_if_current`. The projection check (`cohort open`, generation and
  message match, not already dispatched unless an undelivered mailbox steer) is the guard. A failed
  dispatch is re-offered with backoff 100 ms doubling to 5 s, while the delivery is still open.
  A disabled instance acknowledges each task instead of retrying.
- **`dispatch_if_current`**: wraps the dispatch future. The adapter runs it only while its generation
  is current, returning `Ok(Some(()))`, or `Ok(None)` for a stale offer. The consumer never checks
  generations itself. A disabled-instance error inside the future is carried out of band and
  returned typed.
- **`clear_if_current`**: called on archive, on a disabled instance, and as the no-dispatch release
  of the sticky offer. Must be idempotent.
- **Archive or delete**: the offer is dropped and its retry key cleared. A sticky offer is released.
- **Ownership**: the drain loop and its retries live in one task owned by
  `ProviderContinuationService` (`AbortOnDropHandle`). Dropping the service stops both.
- **Seam**: `ContinuationThreads` (records + dispatch). Implemented for `ThreadManagementCore`. The
  caller must pass an `Arc` of the core, not of the service (the service owns background tasks).
- **Not ported**: upstream's `forkScoped` retry Effect is a spawned task in a `JoinSet`. Retry
  timing is covered by paused-clock tests (100, 200, 400 ms).
