## Not done (in order)

1. **ProviderTurnControlService** (409 lines, tests 331). Blocked on a provider-control read:
   `getProviderControlContext(threadId, {providerThreadId, providerTurnId, attemptId?, messageId?})`,
   which returns `{providerThread, providerTurn, attempt, message, run}`. Upstream ProjectionStore.ts:4534 is a
   targeted SQL read. Rust has no equivalent. Options: add it in `core/` as a read seam over
   `get_thread_records` (correct, loads the whole thread, so it is a perf follow-up), or add it to T13a's
   store. Also needed: `getThreadRecords(runIds)`, `interrupt_turn` / `steer_turn` on the runtime (exist),
   `stop_subagent` (exists, optional), and `projectComposerContextForProvider`, which is not in Rust yet.
   Reuse `runtime_request_service::LiveSessions` for `sessions.get`.
2. **ProviderSwitchService** (219, tests 345) and **ProviderContinuationService** (319, tests 1029).
   They need `ThreadManagementService` dispatch and thread reads. Define a trait for that in `core/`
   (the T13c `OrchestratorPort` will implement it). `ProviderSessionTransitionPolicy` is ready for the
   switch.
3. **RestartContinuation** (339, tests 1121). Split it:
   - Pure part (`restartContinuationRun`, `restartContinuationBlocked`, `hasOpenAwaitedWork`) can be ported now.
     It needs a recovery-state struct with `thread`, `runs`, `providerThreads`, `providerSessions`,
     `providerTurns`, `runtimeRequests`, `turnItems`. Build it from `get_thread_records`. Upstream
     `ProjectionRuntimeRecoveryState` has no Rust type yet.
   - `continueRestartedRun` needs `ServerSettings` (`continueThreadsAfterServerUpdate`, via
     `resolveProjectSettings`), `isNativeMaintenanceCommand`, `threads.dispatch(message.dispatch)`, and
     `threads.recoverDelegatedTask`. Use a trait.
4. **ProviderRuntimeRecoveryService** (787, tests 1605 + 82 regression). Needs RunExecution and the
   recovery projection. Do after item 3.
5. **RunExecutionService** (1543, tests 4481) and **RuntimeRequest** wiring into it. The largest piece.
   Port next after the recovery state. `RunExecutionService` is also needed by item 6.
6. **ProviderTurnStartService** (1291, tests 857 + testkit + memory 25). Calls `RunExecution.startRootRun`,
   so it waits for item 5. Needs `projection.getTurnStartContext`, `getRuntimeRecoveryProjection`,
   `hasUnpairedRunInterruptRequest`, `contextHandoffs`, `deliverContextHandoffs`, the handoff budget helpers
   (`@t3tools/provider-core/server/handoffBudget`, not in Rust), `RuntimePolicy.resolve` (pipeline has
   `runtime_policy.rs`, check its signature), `ProviderAuthService.tryHandlePromptCommand`, and
   `GitWorkflowService` (`pruneWorktrees`, `createWorktree`, in the git crate). `EventSink.write_if_run_current`
   exists in `pipeline/event_sink.rs`.
