# T20 handoff: Settings + keybindings UI

Branch `task/T20-settings`. Code in `crates/app/src/settings/`.

## Architecture
- `view_model.rs`: `SettingsViewModel` + `SettingsSource` trait + `SettingsStore` entity (the seam). `mock_source.rs` backs the demo; T22 implements `SettingsSource` over the live services (`update_client`/`update_server` take wire-JSON patches, so the live impl decodes them to `ClientSettingsPatch`/`ServerSettingsPatch`).
- `view.rs`: `SettingsView` (window content: nav + routed page + dialogs), owns all UI state. Pages are `impl SettingsView` blocks in `panels/*.rs`.
- `layout.rs`/`controls.rs`/`rows.rs`/`dialog.rs`: settingsLayout/ui-primitive ports. Rows are keyed by the settings JSON key (`rows.rs`).
- Logic ports with tests: `keybindings_logic`, `panels_logic`, `search`, `provider_status`, `provider_settings_logic`, `github_account_logic`, `custom_model_editor_logic`, `add_provider_instance_logic`, `project_settings_logic`, `when_tree`, `locale`.
- Demo: `TURIN_SETTINGS=<page> [TURIN_APPEARANCE=dark|light] [TURIN_SETTINGS_OPEN=<menu id>] [TURIN_SETTINGS_SHOT=file.png TURIN_SETTINGS_WINID=<helper>]` (settings/demo.rs). The window-id helper is a 30-line C program (CGWindowListCopyWindowInfo) kept outside the repo; screenshots capture one window only, never the screen.
- `crates/shared/src/server_settings*` was copied from `task/N1-app-runtime` (a full merge conflicts in provider-core/Cargo.lock); drop the copy when N1 merges.

## Status (all pages ported)
Pages (nav order): Project, General, Appearance, Keybindings, Providers, Source Control, Storage, Archive, plus Open source licenses (from General). Dialogs: confirm, add usage hub, project action editor, background activity advanced, add provider wizard.

- General, Appearance, Keybindings (recorder, when-tree builder): `panels/{general,appearance,keybindings}.rs`.
- Providers: `panels/providers.rs` (list + editor, models, usage hubs, health interval, `number_field`), `panels/add_provider.rs`.
- Source Control: `panels/source_control.rs` (repositories defaults, git/GitHub discovery, token + accounts, text generation, review guides).
- Projects: `panels/projects.rs` (own project picker, rename, new-thread defaults, actions, remove). Storage `panels/storage.rs`, Archive `panels/archived.rs`, licenses `panels/licenses.rs`, background activity dialog `panels/background_activity.rs`.
- New seam members (T22 implements): `SettingsViewModel.{source_control, storage_cleanup, licenses, providers, projects, archived_threads}` and `SettingsSource::{rescan_source_control, refresh_providers, update_provider, start_provider_auth, logout_provider, rename_project, remove_project, run_storage_cleanup, unarchive_thread, delete_thread, open_keybindings_file}`.
- Secrets: the GitHub token and hub management key are written through `update_server` with the plain value; the live source must keep them in the secret store and return redaction markers (the panels never display a saved value).
- Logic ports with tests: see the list above plus `provider_form`, `usage_shortcuts`, `slider`, `time_format`, `project_scripts`, `panels/{licenses,storage}.rs` helpers, `dialog::usage_source_id_from_url`.
- Demo env: `TURIN_SETTINGS=<page>` with `TURIN_SETTINGS_OPEN=<id>[,<id>]` (`expand:vcs:git`, `expand:provider:github`, `provider:<instance>`, `scroll:<px>`, `editor-scroll:<px>`, `add-hub`, `add-provider`, `bg-dialog`, `when-first`, `kb-new`, menu ids).
- Screenshots: `docs/screenshots/T20/{dark,light}-*.png`.
- `mod settings` still carries `#[allow(dead_code)]` in main.rs until T22 opens the view from the app's `/settings` route.
- Known gaps and every cut panel: PORTING.md Deviations (T20 rows). Interactions (menus, sliders, recorder, dialogs) were checked by screenshots and code review, not by scripted clicks.
- GPUI gotchas hit: `flex_wrap` + `ml_auto` children can vanish (use a two-sided flex row); content-sized `div`s need `w_full()` to span a flex column; `overflow_hidden` clips to rects only.
