## Confirmed findings (raw)

### [medium] Masked state is fixed at first render: a plain env value that becomes sensitive shows the next typed secret in clear text
- `crates/app/src/settings/view.rs:` · dimension: fix-verification · upheld 2/2
- Evidence: view.rs:401-411 `input_with`: `if let Some(state) = self.inputs.get(&key) { ... return state; }` never updates masking. `.masked(kind == InputKind::Secret)` is applied only in the create branch (view.rs:419-426). providers.rs:1563 keys the generic value input as `env-value-{id}-{index}` for both plain and sensitive rows. providers.rs:1564 picks `secret_commit_input` when `variable.sensitive`, and providers.rs:1605 toggles `entry.sensitive = true` via the lock button. A row first rendered plain creates an unmasked InputState; after the toggle the same state is reused, so the secret the user types next is displayed in clear. The reverse direction leaves a plain value masked as dots.
- Fix: Make masking part of the render, not the creation: include the sensitivity in the input id (e.g. `env-value-{id}-{index}-{sensitive}`) so a toggle creates a fresh masked or unmasked InputState, or update the existing state's masked flag each render in `input_with`. Add a regression test if the input layer allows it.

### [low] Hub id from a URL with forbidden host characters diverges from upstream raw-text slug
- `/Users/jackson/.t3/scratch/2026-10-15-consider-creating-a-t3-code-21b503f2/turin-wt/T20-settings/crates/app/src/settings/dialog.rs:221` · dimension: logic-fidelity · upheld 2/2
- Evidence: url_host (dialog.rs:221-262) only splits scheme, authority, port and userinfo. It never checks host code points, so the authority is returned as the host. The valid-URL and scheme-less cases from the previous QC now match node.
- Fix: In url_host, return None when the authority contains a forbidden host code point (space, %, <, >, ^, |, and the other WHATWG forbidden host code points), so usage_source_id_from_url falls back to the raw text. Add a test with "https://a b.com" expecting "cliproxy-https-a-b.com".
