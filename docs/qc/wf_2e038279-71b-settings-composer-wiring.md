- `crates/app/src/settings/live_source.rs:169` · dimension: fidelity-correctness · upheld 2/2
- Evidence: spawn_feeds: `handle.spawn(async move { ... while let Some(settings) = changes.recv().await { inner.lock()...server = settings; } })` and the same for keybindings (l.177), storage_cleanup (l.185), providers (l.200) only write into `inner`; the only republish hook is `cx.observe(&self.client, move |_, cx| refresh(cx))` (l.161). - Evidence: `refresh_providers` detaches the real work (`cx.spawn(...).detach()` l.183-191) and returns `Task::ready(())` (l.192); WelcomeWizard awaits that task and calls `cx.notify()` immediately (welcome_wizard.rs:207-213), i.e. before the registry refresh completes. The providers watch loop `cx.spawn(async move |_| { while receiver.changed().await.is_ok() { watch(); } })` (l.86-92) updates the RefCell but never notifies any entity, so the wizard keeps rendering the stale `providers()` list until some other interaction re-renders it. Upstream awaits the refresh mutation and the providers atom re-renders on change.
- Fix: Return the real task (`cx.spawn(async move |_| { task.await...; refresh_in_flight.store(false) })`) and, in the watch loop, use the `cx` parameter (`cx.update(|_| ())` or a stored notify hook) so provider changes re-render the gate/wizard.
