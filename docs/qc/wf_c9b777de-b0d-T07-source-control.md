## Confirmed findings (raw)

### [medium] Read cache serves a pre-invalidation entry after a scope invalidation (intermittent)
- `crates/source-control/src/pull_request/read_cache.rs:410` · dimension: logic-fidelity · upheld 2/2
- Evidence: Reproduced with the prebuilt test binary target/debug/deps/turin_source_control-b193c87983ccfcaf (sources unchanged since the build): `invalidates_only_the_changed_scope_across_restarts_and_coalesces_its_next_reads` failed in 1 of 40 quiet runs and in 1 of about 18 in a loop. The failing run panicked at read_cache.rs:881 with 5 of 10 concurrent reads returning "1" where "4" (post-invalidation lookup) is expected. In `Inner::refresh` (lines 405-410) the closure runs `cache_get`, then `cache_invalidate` (memory remove plus store remove), then returns `inner.cache_get(request).await` with no `matches_revision` check. `load_or_lookup` (lines 365-390) can read the still-present store entry (revision "") before the store remove lands and re-insert it into `memory` under the new ReadKey after the memory remove, so the unchecked final `cache_get` returns the stale payload. The handoff note docs/handoff/T07.md ("Known issue") records the failure as unexplained and dismissed as load-related, but the failure reproduces on a quiet machine.
- Fix: Do not return the payload of the post-invalidate `cache_get` unchecked: verify `request.matches_revision(entry.revision)` on it and loop or fall back to a fresh lookup when it fails. Alternatively, remove the store entry before inserting into memory, or make `load_or_lookup` discard an entry whose revision no longer matches the current revision. Then add a deterministic regression test for the interleaving and drop the known-issue note.

### [low] Headcheck git command disables its deadline instead of using the default
- `crates/source-control/src/source_control/repository_service.rs:` · dimension: safety · upheld 2/2
- Evidence: repository_service.rs:654-662 builds `GitCommand { operation: "SourceControlRepositoryService.publishRepository.headCheck", args: ["rev-parse","--verify","HEAD"], timeout: None, .. }`. `GitCommand.timeout` is documented as "`None` disables the deadline" (repository_service.rs:90-91). The bridge maps it to `input.timeout = Some(command.timeout)` (crates/git/src/source_control_bridge.rs:49), and the driver reads `Some(None)` as "waits until git exits" (crates/git/src/git_vcs_driver_core.rs:645-646). So this rev-parse has no timeout. Upstream omits `timeoutMs` for the same call (upstream/apps/server/src/sourceControl/SourceControlRepositoryService.ts:429-433), and upstream GitVcsDriverCore.ts:962 maps undefined to DEFAULT_TIMEOUT_MS. The deviation is not listed in PORTING.md.
- Fix: Set `timeout: Some(Duration::from_secs(30))` (the driver's default) for this command, or give GitCommand an Option that means 'use the driver default' as upstream's undefined does. Keep `None` as 'no deadline' only for the clone path.

### [low] Media client has no connect or response-header timeout
- `crates/source-control/src/github/media_fetch.rs:` · dimension: safety · upheld 2/2
- Evidence: media_fetch.rs:267-270: `reqwest::Client::builder().redirect(reqwest::redirect::Policy::none()).build()` sets no `connect_timeout` or `timeout`. `ReqwestGitHubMediaHttp::get` (around media_fetch.rs:288-290) awaits `builder.send()` with no `tokio::time::timeout`, and `fetch_following_redirects` (media_fetch.rs:119-135) awaits `http.get` on every hop with no deadline. A GitHub or object-store host that accepts the TCP connection and stalls before sending headers holds the media request open with no bound. The API client, by contrast, bounds headers and body with DEFAULT_TIMEOUT (api.rs:35, 741-747). Upstream GitHubMediaFetch.ts is also untimed, so this is parity with upstream rather than a regression, but the dimension asks for timeouts and PORTING.md does not record it. The streamed body must stay untimed.
- Fix: Set `connect_timeout` on the media client and wrap only the `send()` (headers) in a `tokio::time::timeout` per hop, mapping a timeout to the 502 broken-hop path. Do not time the body stream. Record the choice in PORTING.md if it is intentional.
